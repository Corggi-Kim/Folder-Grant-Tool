# 변경·검증 기록

## 2026-10-29 Client 1.1.1 / API 0.4.1

- Client 표기를 **V1.1.1 Build:20261029**, API 패키지·Swagger 버전을 **0.4.1**로 갱신했습니다.
- AD 조회에서 원격·래핑 예외로 전달된 그룹 누락을 놓쳐 Isolated 생성 안내가 나오지 않던 문제를 수정했습니다. 오류 식별자·내부 예외·직렬화된 예외 형식을 확인하며 접근 거부·연결 오류·그 밖의 확인 불가는 계속 보류합니다.
- 실제 그룹 생성 단계에도 같은 판정을 적용합니다. 동의 → 그룹 생성 → 기존 루트·Isolated 기본 RX → 재검증 → 원래 권한 작업 순서는 유지합니다. 폴더 생성이나 준비 결과만으로 BUS 완료 처리를 하지 않습니다.
- 화면 로그에서 반복되는 검증 범위 안내 3줄을 생략하고 상세 파일에는 전체 응답을 보존합니다. ‘직접 가입’은 ‘그룹 등록 여부’, 사용자 확인은 ‘계정 확인 완료’·‘비활성화된 계정’으로 정리했습니다.
- 검증: Client **145개**, API **113개** 통과. API는 실제 PowerShell 인터프리터와 AD·파일 조회 대역으로 누락 분류·생성 분기까지 실행했으며 건너뛴 시험은 없습니다. 기존 폐기 예정 경고 4개가 남습니다. 운영 AD·BUS·SMB에는 작업하지 않았습니다.
- **적용: API·Client 모두 갱신하고, 진행 중인 Job·PowerShell이 없는 상태에서 API 서비스를 재시작합니다.** DB 변경은 없습니다. 기존 Word·PPT와 과거 스크린샷은 덮어쓰지 않습니다.

## 2026-10-27 당시 동작

기준: `main b09100d2e6d53c37d975291576cb5fa23d0e97d9`. 자세한 내용은 [현재 사용·운영 기준](CURRENT_BEHAVIOR.md)입니다.

- 권한 요청만 선택 실행에서 실제 자원을 자동 검증하며, 통과한 항목만 권한 등록·명시적 재실행합니다. 별도 검증 버튼은 두 탭 모두 숨기고 배치·연결은 주석 처리했습니다.
- 신규 프로젝트는 사전 검증 없이 `/project-jobs`에 바로 등록하고 생성·ACL·최종 검증 결과를 확인합니다. 개발용 `/project-jobs/validate`는 남아 있습니다.
- Isolated 그룹만 실제로 없고 준비 조건을 확인한 경우 생성 동의를 받습니다. 별도 준비 Job → 기본 RX → 원래 요청 재검증 → 권한 실행 순서이며 폴더는 생성하지 않습니다. 준비 결과는 BUS 완료 근거에서 제외합니다.
- 권한 요청 이름·부서를 사번 아래에 표시합니다. 신규 프로젝트는 코드·프로젝트명·경로·요청자 정보(직책 제외)를 표시하고 빈 항목도 유지하며, 진행은 4단계로 요약합니다. 버튼은 BUS 신규 조회로 표기합니다.
- 도움말·README·운영 체크리스트를 이 기준에 맞췄습니다. 사용자 수정 Word·PPT와 생성 원본은 재생성하지 않았고 삭제된 베타 파일도 복원하지 않았습니다.
- 최신 자동 시험: **Client 145개 통과 / API 98개 통과·선택 PowerShell 시험 6개 건너뜀**. API 경고 4개는 기존 TestClient/httpx 및 HTTP 422 상수 폐기 예정 경고입니다. 실제 AD·SMB·BUS 작업과 부하 시험은 수행하지 않았습니다.
- Isolated 준비 기능은 API·Client 모두 갱신하고 활성 Job이 없는 상태에서 API 서비스를 재시작해야 합니다. 신규 프로젝트 사전 검증 제거·도움말은 Client 변경입니다. DB 컬럼 변경은 없습니다.

## 2026-10-23 베타 문서 이후 반영

- **실제 요청 검증**: 사용자·보안 그룹·요청 폴더·현재 ACL 또는 생성 준비 상태를 `/validate`로 읽기 전용 확인합니다. 화면 로그는 항목별 결과, 파일은 상세 JSON을 기록합니다. `All`은 별도 검증에서 제외합니다. 기존 `/preview`는 실행 계획 계산용으로 남습니다.
- **목록 조작**: 양쪽 목록 우클릭 행/선택 행/전체 삭제, 권한 BUS 행 읽기 전용과 수동·직접 Excel 입력 편집, 점선 포커스 숨김을 반영합니다.
- **신규 프로젝트**: BUS 원본·서버 기술 상세와 8단계 진행, 긴 오류 스크롤·원문 복사, BUS 완료 재확인을 제공합니다. 최신 서버의 실제 성공·대상 일치가 확인된 경우에만 완료합니다.
- **진행 표시**: 각 요청 시작 시 처리 행 자동 선택, 양쪽 탭 회전 표시, 서버 조회 응답별 단계 전환, 새 작업마다 경과 시간 초기화·완료 시 정지.
- **공통 화면**: 선택 건수·목록 높이·하단 간격 통일, 도움말 명칭, 누락값 `-`, 설정 메뉴 정렬과 공통 상세 열 토글. 신규 탭 생성·재조회 후에도 상세 열 설정을 적용합니다.
- **기존 기능 유지**: 단일 상세 로그 파일, 실패 권한의 명시적 부분 재실행, 시작 로딩·간단 로그인과 저장 선택. 알림·배지는 주석 처리 상태이며 새 요청 자동 감지 확대는 보류입니다.

## 검증 방법과 결과

```bash
# 저장소 루트; PyQt5 및 Client 의존성이 설치된 Python 사용
QT_QPA_PLATFORM=offscreen XDG_CACHE_HOME=/tmp/fgt-cache \
  API/.venv/bin/python -m unittest discover -s Client/tests
# API 작업 폴더에서 실행
cd API
.venv/bin/python -m pytest tests -q
```

- Client: **125개 통과**, 약 11초. HTTP·BUS 테스트 대역을 사용합니다.
- API: **76개 통과·5개 건너뜀**, 약 2초. 선택 시험은 `FGT_TEST_POWERSHELL` 인터프리터 설정이 필요합니다. 이 시험도 스텁 cmdlet 기반이며 실제 AD·SMB 변경을 대신하지 않습니다.
- API 시험에서 보이는 기존 경고 3개는 Starlette TestClient의 `httpx` 사용과 HTTP 422 상수 이름의 폐기 예정 경고입니다.
- 문서: Word 3개·PPT 2개를 LibreOffice로 PDF 변환하고 페이지·슬라이드 배치를 검토했습니다. ZIP/XML·링크·생성 덮어쓰기 방지와 기존 베타본 보존도 확인합니다.
- 실제 Windows·Chrome·BUS·AD·SMB, 실제 업무 인수·성능·부하 검증은 이번 문서 작업에서 수행하지 않았습니다.

## 범위 밖·미제공 사항

서비스 재시작 뒤 진행 Job 자동 재개, 내구성 큐·외부 Worker, 자동 AD/ACL 롤백, 사용자별 인증·권한, 프로젝트 단위 잠금, 자동 로그 순환·보관은 후속 개선 과제입니다. 문서의 개발 완료 표기는 이런 항목의 완료나 오픈 승인까지 의미하지 않습니다.

## 문서 보존과 수정

문서 작성 당시에는 사용자 수정 베타본을 보존했습니다. 이후 사용자가 삭제한 베타 Office 파일은 현재 복원하지 않으며 남은 Office·자산·원본도 자동 재생성하지 않습니다. 최신 운영본은 기존 편집본을 입력으로 복사해 수정·보강했습니다. 생성 도구는 기존 파일을 기본적으로 덮어쓰지 않으며 해시가 달라진 운영본은 `--refresh`로도 덮어쓰지 않습니다. [문서 수정 원칙](README.md#기존-파일과-생성-도구-취급)을 따릅니다.
