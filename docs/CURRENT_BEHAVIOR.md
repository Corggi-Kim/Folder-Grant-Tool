# 현재 사용·운영 기준

2026-10-29 / Client 1.1.1·API 0.4.1 기준입니다. 프로그램 표기는 API **0.4.1**, Client **V1.1.1 Build:20261029**입니다. 문서 날짜와 빌드 날짜는 다릅니다. 이 문서는 이후 바뀐 화면·동작을 설명하며 작성 당시의 Word·PPT를 자동으로 덮어쓰지 않습니다.

## 두 탭의 실행 차이

| 항목 | 권한 요청 | 신규 프로젝트 |
|---|---|---|
| 목록 준비 | 수동 입력·엑셀 불러오기·BUS 요청 조회 | 수동 추가·BUS 신규 조회 |
| 선택 실행 | 실제 자원 자동 검증 → 통과 후 권한 Job 등록 | 사전 검증 없이 생성 Job 등록 |
| 실행 전 검증 실패·주의·확인 불가 | 해당 요청 보류, Job·BUS 미처리 | 사용자 실행의 사전 검증 단계 없음 |
| 실제 서버 처리 | AD 가입/탈퇴·대상 ACL 적용/제거 | 그룹·템플릿 폴더·기본 ACL 준비와 최종 생성 검증 |
| 별도 요청 검증 버튼 | 숨김, 배치·연결은 주석 처리 | 숨김, 기존 구현과 개발용 검증 API 보존 |
| Mock 모드 | 실제 검증 확인 불가로 실행 보류 | 생성 Job 모의 실행 가능, BUS 미처리 |
| 실패 재실행 | 원인 조치 → 선택 실행 확인 → 재검증 → 실패·미실행 단계의 새 Job | 권한 전용 `/retry` 대상 아님. 실제 자원 확인 후 복구 판단 |
| BUS 완료 재확인 | 서버 최신 실제 성공 확인 후 완료만 수행 | 같은 조건으로 완료만 수행, 프로젝트 재생성 안 함 |

권한 검증은 읽기 전용이며 실제 변경의 성공이나 전체 유효 권한을 보장하지 않습니다. 신규 프로젝트는 생성 과정에서 실패할 수 있으므로 최종 결과와 실제 자원을 확인합니다. Job 접수 성공과 작업 성공, BUS 완료 성공은 구분합니다.

## 화면·상세·목록 조작

- 권한 요청 상세: 프로젝트 → 대상 사번 → 이름 → 부서 → 권한 → Role. 빈 값은 `-`입니다.
- 신규 프로젝트 상세와 목록 상세 열: 프로젝트 코드·프로젝트명·경로·요청자 정보. 직책·요청일·승인자·Job ID·템플릿 같은 나머지 항목은 숨깁니다. 처리와 파일 로그에 필요한 원본은 유지합니다.
- 신규 프로젝트는 요청이 없어도 상세 항목을 `-`로 표시합니다. 경로는 서버 실제 경로를 반영하며 아직 정보가 없으면 `-`입니다.
- 신규 프로젝트 진행은 **보안 그룹 생성 → 프로젝트 폴더 생성 → 권한 적용 → BUS 완료 처리**입니다. 권한 적용은 ACL 정리·프로젝트/기본 폴더 권한·최종 생성 검증을 묶으며 모두 성공해야 완료 체크합니다.
- 각 요청 시작 시 처리 행이 자동 선택됩니다. 회전은 작업 중임을 나타내며 서버 Job 조회 응답마다 갱신합니다. 처리 중 다른 행을 선택하면 그 행의 상세를 봅니다.
- 톱니바퀴의 상세 열 표시는 두 탭 공통입니다. 신규 탭을 처음 열거나 BUS 재조회 후에도 적용합니다.
- 권한 요청의 BUS 행은 읽기 전용, 수동·직접 Excel 입력만 편집할 수 있습니다. 양쪽 목록 우클릭 삭제는 화면 목록만 지우며 서버·BUS 원본은 삭제하지 않습니다.
- 실행 중 편집·삭제·추가·충돌 가능한 조회를 막으며, 중지는 이미 적용한 권한을 롤백하지 않습니다.

## Isolated 그룹이 없을 때

이전 FGT의 보안그룹 생성 확인 동작을 복원했습니다. 진행 Isolated 권한 부여에서 실제 그룹 누락만 확인되고 사용자·기존 폴더·생성 OU 등 준비 조건이 맞을 때만 제안합니다. AD 오류 식별자·내부 예외·원격 예외 형식을 확인해 실제 그룹 누락을 구분합니다. 접근 거부·연결 실패·그 밖의 확인 불가 오류는 누락으로 간주하지 않습니다.

1. **계속/취소**를 선택합니다. ‘이번 세션 동안 자동 생성’은 동의했을 때만 현재 실행에 적용하며 파일에 저장하지 않습니다.
2. 동의하면 별도 준비 Job으로 Security DomainLocal 그룹을 만들고 Study 그룹 Description을 복사합니다. 설명 조회 실패 시 빈 설명을 사용합니다.
3. 15초 대기 후 기존 프로젝트 루트와 Isolated 루트에 그룹 SID 기준 RX를 적용합니다. 재귀·상속 플래그를 추가하지 않습니다.
4. 원래 요청을 다시 검증하고 통과한 경우에만 사용자 권한 작업을 실행합니다.

**Isolated 폴더 자체는 생성·복사하지 않습니다.** 폴더까지 없으면 보류합니다. 기존 그룹의 일반 검증과 ETC의 그룹-only 처리는 유지합니다. 준비 성공만으로 BUS 완료를 처리하지 않습니다. 준비·원래 권한 Job은 식별과 결과가 분리됩니다. 준비 실패·부분 성공은 실제 그룹·ACL을 확인해야 하며 일반 권한 `/retry`로 준비 Job을 재실행하지 않습니다.

## 완료·로그·시작 준비

BUS 완료는 BUS 원본, `executor_mode=powershell`, 최종 `status=succeeded`이며 대상이 일치하는 경우에만 허용합니다. 수동·Excel·Mock·검증 결과·그룹 준비 결과·부분 성공·실패·불확실 결과는 완료 근거가 아닙니다. 완료 재확인은 새 권한 작업 없이 최신 서버 결과와 BUS 완료만 확인합니다.

시작 로딩은 API 확인 → BUS 로그인 → 권한 목록 → 신규 프로젝트 목록 순서입니다. 저장 계정이 없으면 계정·암호 전용 창을 띄우고 저장 여부를 직접 선택합니다. 이후 새 요청은 각 BUS 조회 버튼으로 갱신합니다. 알림·숫자 배지·주기 감지는 비활성화 상태이며 자동 감지 확대는 보류입니다.

화면 로그는 요약과 자동 검증의 항목별 결과를 표시하며 반복되는 검증 범위 안내는 생략합니다. 계정·그룹 결과는 ‘계정 확인 완료’, ‘그룹 등록 여부’로 표시합니다. `C:\FGT\Log\access.log` 한 파일은 날짜·시간·상세 응답을 누적합니다. 화면 로그 지우기는 파일을 삭제하지 않습니다. 새 작업마다 경과 시간을 초기화하며 완료 시 멈춥니다.

## 업데이트와 확인

| 변경 | 적용 |
|---|---|
| 신규 프로젝트 사전 검증 제거, 화면·도움말 | Client 갱신 |
| 권한 요청 자동 검증 | 기존 `/access-jobs/validate` 지원 API 필요, 미지원 서버는 API도 갱신 |
| Isolated 그룹 생성 확인·준비 | API와 Client 모두 갱신, 새 `/access-jobs/prepare-group` 필요 |
| 그룹 누락 판정·검증 문구 수정(0.4.1), 로그 안내 생략(1.1.1) | API·Client 모두 갱신, 작업이 없는 상태에서 API 서비스 재시작 |
| 서버 코드·설정 갱신 | 활성 Job·PowerShell을 확인하고 작업이 없는 상태에서 API 서비스 재시작 |

이번 기능에는 DB 컬럼 변경이 없습니다. 서비스 재시작 후 진행 Job 자동 복구, 자동 롤백, 사용자별 인증·권한, 프로젝트 잠금, 자동 로그 순환은 제공하지 않습니다. 평문 설정과 공유 API Key·HTTP의 접근 범위는 배포 환경에서 관리합니다.

자동 시험: **API 113개 통과(선택 PowerShell 시험 포함) / Client 145개 통과**. 실제 Windows·Chrome·BUS·AD·SMB 인수·성능·부하 시험을 뜻하지 않습니다. 시험·승인은 [오픈 확인 목록](OPEN_CHECKLIST.md)에 별도로 기록합니다.
