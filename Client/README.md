# Folder Grant API Client

현재 버전은 **v1.1.0**, 빌드는 **2026-10-22**입니다. 메인 화면 오른쪽 하단에 `V1.1.0 Build:20261022`로 표시됩니다.

BUS 조회·완료 처리와 기존 PyQt 화면을 유지하면서, 권한 부여·해제 및 신규 프로젝트 생성은 API 서버에 맡기는 독립 Windows 클라이언트입니다. 기존 프로그램과 `API/`를 수정하거나 import하지 않습니다.

[Client 설계·사용·유지보수 Word](../docs/Client_설계_사용_유지보수.docx) · [운영 문서 목록](../docs/README.md)

## 설치와 실행

Python 3.11 이상과 Google Chrome이 필요합니다. 클라이언트 PC에서 AD 관리 도구 또는 PowerShell 권한 작업 환경은 필요하지 않습니다. BUS 접속 및 API 서버 연결이 가능한 PC에서 실행하세요.

```powershell
cd C:\Folder-Grant-Tool\Client
py -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python ".\Folder Grant API Client.pyw"
```

실행 코드는 `Folder Grant API Client.pyw` 한 파일입니다. `assets/`는 아이콘·로고이며 같은 폴더에 유지하세요. Selenium이 Chrome 드라이버를 자동으로 찾거나 설치하므로, 제한된 네트워크에서는 Chrome에 맞는 드라이버를 미리 준비해야 합니다. 초기 실행 오류를 확인할 때는 위처럼 PowerShell에서 `python`으로 실행하세요.

## 처음 설정

첫 실행의 API 설정 화면에서 아래 값을 입력하고 **연결 확인** 후 저장합니다. 주소나 키는 메인 화면의 **API 연결 설정**에서 다시 변경할 수 있습니다.

| 설정 | 값 |
|---|---|
| API 주소 | 기본값 `http://192.168.1.10:8000`, 실제 서버 주소로 변경 |
| X-API-Key | 서버 `API\.env`의 `FGT_API_KEY` 값 |
| BUS 계정 | 저장 정보가 없으면 로딩 중 전용 로그인창에서 입력. 이후 톱니바퀴의 **BUS 계정 설정**에서 변경 |

연결 확인은 `/health`와 API Key가 필요한 `/ready`를 함께 호출합니다. API Key는 `C:\FGT\conf\api_client.json`에 평문 저장됩니다. 이 파일을 저장소나 공유 폴더에 넣지 마세요. BUS 계정 저장 기능 및 `C:\FGT\conf\login.json`은 기존 프로그램과 공유하며, 저장을 선택하면 BUS 비밀번호도 해당 파일에 저장됩니다. API Key는 로그에서 마스킹합니다.

상세 로그는 날짜별 분리 없이 `C:\FGT\Log\access.log`에 날짜·시간과 함께 누적 기록합니다. 화면 작업 로그는 API 응답을 요약해 표시하며, 화면의 로그 지우기는 파일 기록에 영향을 주지 않습니다. BUS 다운로드는 `C:\FGT\ef`, BUS 디버그 자료는 `C:\FGT\debug`를 사용합니다. 해당 경로에 쓰기 권한이 필요합니다.

## 기능

### 시작 준비

실행 시 작은 로딩창에서 회전 애니메이션과 함께 **API 연결 확인 → BUS 로그인 → 권한 요청 조회 → 신규 프로젝트 조회** 순서로 준비합니다. 완료된 단계에는 체크가 표시되고 두 목록을 받은 뒤 메인 화면을 엽니다. 최초 API 설정이 없으면 연결 설정을 입력하고, BUS 계정이 없으면 전용 로그인 창에서 아이디·비밀번호를 입력합니다. `계정 정보 저장`은 직접 선택하며 기본은 해제입니다. 로그인 창은 입력 화면만 간소화한 것으로 일반 설정창과 동일한 계정 처리 함수를 사용합니다. 로그인 버튼으로 입력을 확정하면 체크 여부에 따라 계정을 저장하거나 저장된 계정만 제거하고 현재 실행에서 사용합니다. 테마·디버그 등 다른 설정은 보존하며 취소하면 파일을 바꾸지 않습니다. 로그인 실패 후 재시도하면 계정을 다시 입력할 수 있습니다. 톱니바퀴의 일반 설정창은 유지합니다.

연결이나 조회 실패 시 **다시 시도**, 또는 **메인 화면 열기**로 진행할 수 있습니다. 단계별 응답을 120초까지 기다린 후 지연 안내를 표시합니다. 진행 중인 연결·다운로드가 끝나기 전에는 중복 재시도를 막습니다. 메인 화면을 먼저 열어도 진행 중인 조회의 결과는 반영됩니다.

알림·숫자 배지 기능은 현재 주석 처리되어 비활성화되어 있습니다. 탭 배지, 새 요청 안내, 설정의 BUS 요청 알림·주기 설정, 알림용 BUS 감시 세션과 타이머가 실행되지 않습니다. 관련 구현은 코드에서 보존합니다. 시작 시 두 목록을 조회하는 동작과 각 탭의 수동 BUS 조회·권한 작업·완료 처리는 유지됩니다. 이미 받은 목록은 탭 이동 시 재조회하지 않습니다.

### v1.1 화면 구성

- 상단에 API·BUS 연결 상태와 서버 주소를 표시합니다. 연결이 아직 확인되지 않았으면 미확인으로 표시합니다. 실행 모드는 내부 결과 검증에 사용하고 상단에는 표시하지 않습니다.
- **권한 요청 / 신규 프로젝트** 탭으로 이동합니다. 신규 프로젝트의 생성·중지 기능도 같은 창 안에서 사용합니다.
- 요청 목록 오른쪽에 선택한 요청의 사번·프로젝트·폴더·Role, 실제 서버 단계 상태 및 결과를 표시합니다.
- 하단의 **요청 검증**은 실제 자원의 읽기 전용 조회, **선택 실행**은 실제 Job 등록입니다. **BUS 완료 재확인**은 서버의 최신 성공 여부를 확인한 뒤 BUS 완료만 처리합니다.
- 로그는 **작업 로그** 제목을 눌러 접거나 펼칠 수 있습니다. 라이트·다크 전환은 상단 달/해 아이콘로 수행하며 선택한 테마는 저장됩니다.
- **톱니바퀴 메뉴**에서 API 설정, BUS 계정 설정, 도움말에 접근합니다. 이름·부서·Role·별도 Level3 열은 기본적으로 상세 패널에 정리합니다. **상세 열 표시**는 두 탭의 공통 설정입니다. 켜면 권한 목록의 상세 열과 신규 프로젝트 목록의 프로젝트 코드·프로젝트명·경로·요청자 정보 열을 함께 표시하고, 끄면 요약 목록으로 돌아갑니다. 신규 탭을 처음 열거나 BUS 재조회 후에도 설정을 적용합니다. 켜진 상태는 메뉴 문구 뒤 ✓로 표시합니다.
- 표의 `Level2 / Level3` 표시는 화면에서만 합쳐집니다. 서버로 보내는 원래 두 필드와 기존 BUS 매칭 데이터는 유지됩니다.

최신 Qt 프로그램을 샘플 데이터로 실행하여 캡처한 [라이트 테마](../docs/release-assets/access.png), [다크 테마](../docs/release-assets/access-dark.png)를 확인할 수 있습니다. 샘플 캡처는 실제 서버·BUS에 접속하지 않습니다.

### 작업

- **BUS 요청 조회**: Selenium으로 BUS 진행·종료 권한 요청을 조회합니다.
- **신규 프로젝트** 탭: BUS 신규 프로젝트 생성 요청을 불러옵니다. 화면의 수동 추가는 API 생성할 요청을 목록에 추가합니다.
- **엑셀 불러오기 / 파일 드래그 / 수동 입력**: 기존 Excel(`.xlsx`, HTML 형식 `.xls`)·수동 요청 흐름을 유지합니다.
- **선택 실행**: 선택된 권한 요청을 API에 등록하고 Job ID로 최종 상태를 조회합니다. 진행·종료, 권한 부여·해제, 사번, 프로젝트 코드, Level2·Level3·Role을 서버 계약으로 변환합니다. `26-012` 같은 BUS 표기는 `26012`로 변환합니다.
- **요청 검증**: API 서버에서 실제 사용자·보안 그룹·요청 폴더·현재 ACL을 조회합니다. 신규 프로젝트도 같은 버튼으로 생성 준비 상태를 확인하며, 각 결과를 화면 로그에 표시합니다. 실제 권한 변경·Job 등록·BUS 완료는 하지 않습니다.
- **중지**: 다음 작업 등록을 멈추고 실행 Job 취소를 요청한 뒤 최종 상태를 조회합니다. 서버의 실행 중인 단일 PowerShell 단계는 즉시 종료되지 않을 수 있습니다.
- **BUS 완료 재확인**: 선택한 BUS 요청번호로 서버 상태를 백그라운드에서 다시 조회하고, 실제 성공이 확인된 요청만 BUS 완료를 처리합니다. 클라이언트 조회 오류 뒤 서버에서 완료된 작업도 다시 확인할 수 있습니다. 권한 Job을 재등록하지 않으며 API가 성공하고 BUS만 실패했다면 BUS 완료만 재시도합니다.
- **테마 / 테이블 / 로그**: 기존 화면 기능을 유지합니다. 실행 중에는 행 편집·삭제 및 파일 드롭을 제한합니다.

신규 프로젝트 탭 하단에도 권한 요청과 같은 **선택 N건**을 표시합니다. 두 탭의 선택 건수·자동 완료 옵션·버튼 간격과 문구를 통일하고, 목록의 위아래 경계와 작업 로그 위치도 맞췄습니다. 체크·전체 선택·추가·삭제·재조회 시 즉시 갱신됩니다.

두 목록의 우클릭 메뉴에서 **행 삭제 / 선택 행 삭제 / 전체 삭제**를 사용할 수 있습니다. 선택 행 삭제는 체크된 항목을 지우며, 화면 목록에서만 제거합니다. BUS 요청과 서버 Job 이력은 삭제하지 않습니다. 실행 중에는 두 목록 모두 삭제를 막습니다. 셀의 점선 포커스 표시는 숨기고 행 선택·키보드 탐색은 유지합니다.

### 신규 프로젝트 선택 요청 상세

선택 요청 상세와 목록의 상세 열은 **프로젝트 코드·프로젝트명·경로·요청자 정보(사번·이름·부서/팀 등)**만 표시합니다. 목록의 선택 열과 상태 열은 유지합니다. 요청일·승인자·요청번호·Job ID·보안 그룹·템플릿·시작/완료 시각은 상세 항목에서 숨깁니다. 원본 데이터와 서버 응답은 내부 처리·상세 로그에 보존합니다. 경로는 서버가 반환한 실제 프로젝트 경로를 우선 반영하며, 아직 경로를 받지 않았고 BUS 원본에도 없으면 `-`로 표시합니다.

요청이나 선택된 행이 없어도 프로젝트 코드·프로젝트명·경로·요청자 항목을 `-`로 표시합니다. 화면 진행은 **보안 그룹 생성 → 프로젝트 폴더 생성 → 권한 적용 → BUS 완료 처리**의 4단계입니다. 권한 적용에는 기본 ACL 정리·프로젝트/기본 폴더 권한·최종 생성 검증을 묶어 표시하며, 관련 서버 단계가 모두 성공해야 성공 체크를 표시합니다. 실제 서버 처리 단계와 상세 로그는 유지합니다. 실제 서버의 단계 상태를 조회해 진행·성공·실패·미실행·중지를 표시하며, 모의 실행은 실제 성공과 구분합니다. 요청 검증만으로 생성 단계가 완료됐다고 표시하지 않습니다. 수동 요청에는 BUS 완료 제외를 표시합니다.

진행 조회는 화면 표시용으로 기존 실제 Job 결과를 덮어쓰지 않습니다. 각 요청을 시작하면 처리할 행을 자동 선택합니다. 처리 중 다른 행을 선택하면 해당 행의 정보와 상태를 보여줍니다. 두 탭 모두 진행 중인 단계에 회전 애니메이션을 표시하고, 서버 응답에 맞춰 성공·실패·미실행 등으로 전환합니다. 실시간 푸시가 아닌 기존 Job 조회 응답 기준의 갱신입니다. 상세 항목·진행 단계와 긴 오류는 각 스크롤 영역에서 확인할 수 있으며, 두 탭의 목록·로그 높이는 유지합니다.

## 요청 검증 결과와 타이머

화면 로그에 사용자·그룹·가입 여부, Level1·Level2·Level3와 Role 하위 폴더, 현재 ACL을 항목별로 표시합니다. 신규 프로젝트는 그룹·폴더가 없어도 생성 예정이면 정상이며, 필요한 생성 위치·템플릿 구조를 검사합니다. 기본 All 폴더는 별도 검증하지 않습니다. 상세 JSON은 기존 access.log에 기록합니다.

조회 결과는 통과·실패·주의·확인 불가·해당 없음으로 구분합니다. 연결 실패·권한 부족·제한 초과를 ‘없음’이나 ‘통과’로 표시하지 않습니다. ACL은 참고용 조회이며 전체 유효 권한이나 실제 변경 성공을 보장하지 않습니다. 검증 후 실행 시점의 변경도 가능하므로 실제 Job 결과를 별도로 확인하세요.

검증 API가 없는 구버전에서 갱신한다면 API와 Client를 함께 업데이트하고 API 서비스를 재시작해야 합니다. 검증은 API 서버의 PowerShell 모드에서 실제 조회하며, Mock에서는 실제 검증을 했다고 표시하지 않습니다. 구버전 서버는 업데이트 안내를 표시하고 Preview나 실제 실행으로 우회하지 않습니다.

경과 시간은 새 작업·검증·완료 재확인마다 초기화하고 완료되면 멈춥니다. OS 시계 변경에 영향받지 않는 시계를 사용하며 이전 서버 Job의 시작 시각을 현재 요청 시간으로 표시하지 않습니다.

## 완료 처리 조건

자동·수동 완료 처리 모두 **BUS에서 조회한 요청**이며 `executor_mode=powershell`, `status=succeeded`일 때만 허용합니다. 신규 프로젝트에도 같은 조건을 적용합니다. 중지 후 자동 완료는 실행하지 않습니다.

| API 결과 | 화면 / BUS 처리 |
|---|---|
| 요청 검증 | 조회 결과를 항목별로 표시, Job·BUS 미처리 |
| 개발용 Preview | 실행 계획만 계산, BUS 미처리 |
| Mock | `모의완료`, BUS 미처리 |
| 실제 성공 | `API 성공`, BUS 요청만 완료 가능 |
| 부분 성공 / 실패 / 취소 | 결과 및 단계 로그 표시, BUS 미처리 |
| API 조회 오류 | 등록 결과 확인 필요 표시, BUS 미처리 |

직접 연 Excel 파일과 수동 입력은 `source=test-client`이고 BUS 자동·수동 완료 대상에서 제외됩니다. BUS 조회 행은 읽기 전용이며 목록에서 편집할 수 없습니다. 수동 입력·직접 불러온 Excel 항목만 편집할 수 있고, 편집하면 이전 결과를 무효화하고 새 요청번호를 사용합니다. BUS 완료가 끝난 행은 같은 세션에서 다시 완료 처리하지 않습니다.

### 300초 초과 및 완료 보류

API 서버 PowerShell의 기본 실행 제한은 단계당 3시간(`10800`초)입니다. 기존 서버 `.env`에 `FGT_POWERSHELL_TIMEOUT_SECONDS=300`이 남아 있으면 `10800`으로 변경하고 실행 중 작업이 없는 상태에서 `Restart-Service FolderGrantApi`를 실행해야 합니다. 클라이언트만 업데이트해서는 기존 서버 설정이 변경되지 않습니다.

**BUS 완료 재확인**을 누르면 최신 Job을 조회합니다. 실행 중이면 보류하고 나중에 다시 조회할 수 있습니다. 조회에 실패하면 화면에 남은 과거 성공 결과를 근거로 완료하지 않습니다. 요청번호가 다른 응답도 완료 대상으로 사용하지 않습니다.

`POWERSHELL_TIMEOUT`은 서버가 PowerShell 프로세스를 종료하고 기록한 실패입니다. 일부 권한만 변경됐을 수 있어 실패·부분 성공은 BUS 완료 대상이 아닙니다. 제한 시간을 늘리거나 폴더를 복구해도 기존 실패 Job 자체는 변경되지 않습니다.

실패·부분 성공이 표시된 권한 요청을 선택하고 **선택 실행**을 누르면 재실행 확인창이 뜹니다. 원인을 조치한 뒤 확인하면 서버가 **새 Job으로 실패한 단계와 이후 단계만 실행**합니다. 이전 성공 단계는 그대로 유지하고 기존 Job 이력을 보존합니다. 성공 후 자동 BUS 완료 또는 BUS 완료 재확인은 원래 BUS 요청에 연결된 최신 재실행 결과를 확인합니다. 요청 검증은 재실행 대신 읽기 전용 조회만 수행하며 기존 실행 결과와 재시도 연결을 보존합니다.

이 기능은 **API 서버와 클라이언트를 함께 업데이트하고 API 서비스를 재시작**해야 사용할 수 있습니다. DB 스키마 변경은 없습니다. 구버전 서버는 클라이언트에서 업데이트 안내를 표시하며 새 요청번호를 임의로 만들어 우회하지 않습니다. 앱을 재시작해 실패 결과가 아직 표시되지 않으면 BUS 완료 재확인 또는 선택 실행으로 서버 결과를 확인한 뒤 재실행하세요.

신규 프로젝트 생성 화면의 **성공 후 BUS 자동 완료**를 끄면 서버 작업만 수행합니다. 이후 **BUS 완료 재확인**을 누르면 체크한 미완료 BUS 요청을 서버에서 다시 조회하고, 실제 성공이 확인된 항목만 BUS 완료를 처리합니다. 자동 완료 옵션이 꺼져 있어도 이 명시적 완료 버튼은 사용할 수 있습니다. 서버 Job 등록·프로젝트 재생성·요청 검증·Job 취소는 호출하지 않습니다. 수동 항목·이미 BUS 완료된 항목·요청번호가 없는 항목은 제외합니다. 조회 실패·불일치·실행 중·부분 성공·Mock 결과는 완료하지 않으며 과거 캐시 성공으로 우회하지 않습니다. **요청 검증**은 이 경우에도 실제 조회만 수행하며 보관된 실행 성공 결과를 덮어쓰지 않습니다.

## 도움말

톱니바퀴의 **도움말**에서는 처음 사용하기, 버튼 안내, 문제 해결, 설정과 기록을 탭별로 볼 수 있습니다. 현재 화면 테마에 맞춰 표시됩니다.

## 요청번호와 재시도

BUS 원본 요청번호가 다운로드에 있으면 식별 재료로 우선 사용하고, 없으면 요청일 등 원본 필드를 사용합니다. 대상자·프로젝트·작업·경로·Role 등과 함께 SHA-256 해시를 만들어 `BUS-<해시>`를 API 요청번호로 사용합니다. 원본 번호를 그대로 API 요청번호로 보내는 방식은 아닙니다. 행 순번은 식별에서 제외합니다. 동일 요청을 다시 불러와도 같은 API 요청번호를 사용하고, 등록 응답이 유실되면 `by-request` 조회로 원래 Job을 복구합니다. 서버가 `replayed: true`로 기존 결과를 반환하면 화면 로그에 `이전 작업 결과 · 재실행 안 함`을 표시합니다. 폴더를 복구해도 같은 요청번호로는 PowerShell이 다시 실행되지 않습니다. 일반 실행에서는 임의로 새 요청번호를 만들어 재등록하지 않습니다. 명시적 실패 작업 재실행만 서버가 이전 Job에 연결된 별도 요청번호를 발급하며, 같은 이전 Job에 대한 재실행 접수는 중복 생성하지 않습니다.

원본 식별자가 없고 모든 필드가 같은 별도 요청은 구분할 수 없습니다. 반대로 원본 행 필드가 변경되면 식별자가 달라질 수 있습니다. BUS 완료 대상 선택은 기존 Selenium의 사번·프로젝트·경로 및 요청 종류 매칭을 유지하므로, 동일 조건의 복수 요청은 실제 BUS에서 확인해야 합니다.

다른 운영자가 동일 BUS 요청을 등록해 payload 충돌(HTTP 409)이 발생하면 기존 Job을 조회하고 현재 Preview의 작업 종류·대상·권한·메타데이터와 비교합니다. 실행 계획이 일치할 때만 원래 Job을 복구하며 기존 요청자의 서버 이력을 유지합니다. 계획이 다르면 충돌로 표시하고 BUS 완료를 실행하지 않습니다. 수동 요청의 충돌은 자동 복구하지 않습니다.

수동 요청번호는 항목별로 새로 생성되며 같은 화면 항목의 재시도에서는 유지됩니다. 앱을 재시작해서 다시 수동 입력하면 별도 요청이 됩니다. Mock 작업도 서버 DB에서 요청번호를 차지하므로 동일 BUS 요청을 실제 실행하려면 Mock 검증용 서버·DB와 실제 실행 서버·DB를 분리하세요.

## 검증 순서

1. 서버를 Mock 모드로 실행하고 API 연결·인증을 확인합니다.
2. 수동 권한 요청 1건을 추가하고 **요청 검증**으로 실제 그룹·경로의 조회 결과를 확인합니다. Mock 서버는 실제 조회를 생략하고 확인 불가 안내를 표시합니다. 기존 개발용 Preview API는 계획만 계산합니다.
3. 권한 탭의 **선택 실행**으로 Mock Job 결과와 SQLite 이력을 확인합니다. BUS 완료는 실행되지 않아야 합니다.
4. 신규 프로젝트 화면의 수동 추가·요청 검증·Mock 결과도 확인합니다.
5. BUS 조회로 진행·종료·신규 요청을 불러오고 대상 행과 원본 BUS 정보를 비교합니다.
6. 테스트용 AD·폴더 자원이 준비된 별도 서버·DB에서 PowerShell 모드를 사용합니다. 자동 완료를 끈 상태로 1건 실행합니다.
7. 서버 결과 및 실제 그룹·폴더 권한을 확인한 후 BUS 완료만 실행합니다.
8. 검증된 테스트 요청으로 자동 완료·중지·취소·BUS 실패 후 완료 재시도를 확인합니다.

서버가 `FGT_EXECUTOR_MODE=powershell`이면 권한 탭의 **선택 실행**, 또는 신규 프로젝트 탭의 **선택실행**은 실제 AD·폴더 ACL을 변경합니다.

## 자동 테스트

저장소 루트에서 클라이언트 가상환경으로 실행합니다. 실제 BUS·AD 작업은 호출하지 않습니다.

```powershell
.\Client\.venv\Scripts\python.exe -m unittest discover -s Client\tests -v
.\Client\.venv\Scripts\python.exe -m py_compile ".\Client\Folder Grant API Client.pyw"
```

계약 변환, Preview·Mock 완료 차단, 실제 성공의 완료 허용, 요청 식별, 모의 HTTP 서버를 통한 오류·복구·취소 및 offscreen Qt 작업 스레드 수명을 검사합니다. Linux 환경에서는 `QT_QPA_PLATFORM=offscreen`을 사용할 수 있습니다.

Windows GUI·Chrome·실제 BUS 사이트는 해당 PC에서 확인해야 합니다. 서버의 Background Task 및 재시작 시 작업 복구 제한은 그대로 유지됩니다. 작업 조회 오류가 발생하면 로그의 request_id/job_id로 서버 이력을 확인하세요. 창 닫기는 API 및 BUS 스레드 종료를 기다리며, 실행 중인 서버 작업이나 브라우저 응답이 늦으면 종료도 늦어질 수 있습니다.
